# SEO HATTI — аудит и внедрение

Дата: 11 октября 2026, Москва. Основной адрес: https://hatti-brand.ru/.
Ветка: `codex/seo-hatti`. Изменения не опубликованы.

Решение владельца: **оставить сайт одностраничным**. Предложения новых категорийных, товарных и юридических страниц отложены; видимые тексты и URL интерфейса сохраняются. Нового согласования этих страниц сейчас не требуется.

## Резюме

- Next.js 16.3.3, App Router; каталог уже серверный, перестройка SSR не нужна.
- Публичный сайт до изменений: robots и sitemap — 404; canonical и JSON-LD отсутствуют.
- Добавлены метаданные, canonical главной, OG/Twitter, иконки, robots, image sitemap, Organization/WebSite.
- Видимые тексты, CSS, шрифты, изображения в интерфейсе, URL существующих ресурсов и покупательские сценарии сохранены.
- Alt оригинальных 20 фотографий составлены после просмотра; описания загрузок из редактора сохранены.
- Физической точки нет. LocalBusiness, Product/Offer, выдуманные цены, наличие и отзывы не добавлены.
- Владелец подтвердил Россию как будущую географию доставки и написания Хатти/Хати. На сайте продажи пока не начались.
- Публичный каталог содержит 36 карточек, локальный — 19: замеры этих версий нельзя смешивать.
- Мобильный лабораторный LCP требует отдельной оптимизации; текущие правки не доказывают его улучшение.

## Проект расширения — только предложение

- `/catalog/`, `/catalog/tshirts/`, `/catalog/caps/`, `/catalog/covers/`, `/catalog/cases/`.
- `/catalog/{category}/{slug}/` — серверная карточка, существующий slug сохраняется в данных. До внедрения проверить уникальность, стабильность и механизм смены категории; альтернативно `/products/{slug}/`, чтобы категория не меняла URL изделия.
- Title категории: `{Категория} HATTI — черкесская одежда и аксессуары`; description по реальным товарам и модели обращения; H1 — согласованное название категории.
- Title изделия: `{Название} — {тип изделия} HATTI`; description только по опубликованным данным. H1 — существующее название изделия.
- Ссылки главная → категория → карточка; карточка → категория и главная; BreadcrumbList только при реальной видимой цепочке.
- Product/Offer только после реальных публичных цен/условий; карточки без цен не получают фиктивный Offer. Для расширенного результата одних ссылок на соцсети недостаточно.
- Не заменять якоря и нынешние URL без согласования. При появлении новых адресов старые не удаляются; реальные смены опубликованных URL — отдельная таблица 301. Придумывать редиректы с пока несуществующих старых карточек не нужно.
- `/about/`, `/delivery/`, `/returns/`, `/contacts/` и документы — после предоставления и утверждения реальных сведений. Это добавление индексируемого контента, поэтому требуется решение владельца.

Контент: утверждённые владельцем истории принтов и дропов, lookbook, размеры, уход, сведения о бренде и доставке. Значения 12 звёзд/3 стрел и исторические объяснения — только по материалам владельца с проверяемыми источниками; автоматически не сочинять.
