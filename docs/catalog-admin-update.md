# Галерея, порядок карточек и цены HATTI

Все три функции доступны в существующей админке `/aloidimihdyrt`. Сетка, категории, варианты товара и локальная корзина сохранены.

## Изменения БД

Таблица `hatti_products` получает:

| Поле | Тип / назначение |
| --- | --- |
| `images` | JSONB: упорядоченный массив `{ src, alt }`, максимум 10 фото |
| `sort_order` | integer: порядок главной страницы |
| `price`, `old_price` | numeric(14,2), пустое значение или положительное число |
| `currency` | RUB: все цены вводятся, сохраняются и показываются в рублях |
| `price_from` | boolean, префикс «от», по умолчанию false |
| `show_price` | boolean, по умолчанию true |

Старое `image` остаётся обложкой и синхронизируется с первым фото. Миграция переносит прежнее изображение в начало галереи, а `sort_order` заполняет в прежнем порядке `ORDER BY id`. Цены существующих товаров остаются пустыми. Есть индекс `(sort_order, id)`. Таблица `hatti_media` продолжает хранить загрузки; её схема не меняется. `hatti_catalog_meta` получает отметку `gallery_order_price_v2` после автоматического применения.

Миграция: `db/migrations/002_product_gallery_order_price.sql`. Она выполняется транзакционно, повторный запуск сохраняет изменённые галереи, цены и порядок.

**Как применить:** после обновления приложения существующий механизм инициализации сам выполнит миграцию при первом обращении к каталогу. Пользователю БД нужны права на изменение таблицы и создание индекса, как и для прежней инициализации схемы. Можно предварительно выполнить содержимое файла миграции в Supabase SQL Editor, подключённом к нужному проекту. Для существующей БД достаточно этого файла; пересоздавать таблицы не нужно. При ручном запуске через настроенное подключение PostgreSQL: `psql --set ON_ERROR_STOP=1 --file=db/migrations/002_product_gallery_order_price.sql`.

В локальном режиме без `DATABASE_URL` старый `.data/products.json` нормализуется при чтении: фотографии и прежний порядок сохраняются. Новые поля записываются при следующем сохранении. Рабочая БД при разработке этих изменений не использовалась.

## Проверка функций

1. **Фото:** откройте товар в админке, загрузите несколько JPG/PNG/WebP или перетащите файлы в галерею. Проверьте превью; измените порядок за ручку и кнопками; добавьте описания фото, удалите одно и сохраните товар. Первое фото становится обложкой. На главной проверьте стрелки, точки, клавиши ←/→, Home/End и свайп. Эти действия не должны открывать товар. Клик по изображению открывает карточку с той же галереей. У одного фото нет управления, у пустой галереи есть заглушка.
2. **Порядок:** в разделе «Порядок карточек» перетащите строку или нажмите вверх/вниз, затем «Сохранить порядок». Проверьте сообщение и главную страницу. Новая карточка попадает в конец. При изменении состава каталога в другой сессии устаревшая сортировка отклоняется; обновите админку. Ошибка сохранения оставляет несохранённый порядок доступным для повторной попытки.
3. **Цена:** задайте `12500`, старую цену `15000` и «от». Все цены указываются в рублях, выбора валюты нет. На главной и в открытой карточке должны появиться `от 12 500 ₽`, зачёркнутые `15 000 ₽` и скидка `17%`. Проверьте дробную цену с точкой или запятой, отсутствие цены и выключенный показ. Ноль, отрицательные значения и более двух десятичных знаков отклоняются. Если старая цена не больше текущей, скидка не показывается.
4. **Регрессия и размеры:** проверьте категории, выбор размера/модели, добавление товара в корзину. Проверьте 390, 768 и 1440 px, длинную цену и reduced motion. Для карусели сохраняется квадратное место в сетке; остальные слайды монтируются только при переключении.
5. **Защита:** без авторизации запись товаров, загрузка и сортировка возвращают 401; запросы изменения с чужим Origin — 403. Сервер проверяет реальные данные изображения, максимум 5 МБ на файл, максимум 10 файлов на запрос и максимум 10 фото при сохранении товара. Фальшивый PNG, повреждённое изображение и неподдерживаемый формат отклоняются.

После записи API инвалидирует главную и админку. Открытая главная в том же браузере обновляется через BroadcastChannel; при возвращении фокуса запрашивает актуальные данные. Главная продолжает работать в `force-dynamic`.

## Установка и запуск

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm dev
```

Новых переменных окружения нет. Существующие `DATABASE_URL`, настройки TLS и `HATTI_ADMIN_*` остаются необходимыми для production. `sharp` 0.35.4 объявлен прямой зависимостью; дополнительных библиотек для карусели или drag & drop нет. Сервер уменьшает новые загрузки до 1600 × 1600 с сохранением пропорций, преобразует в WebP и удаляет метаданные. Оригинальные файлы каталога не переписываются.

Если reverse proxy ограничивает тело запроса, для одновременной загрузки 10 файлов по 5 МБ настройте предел не менее 51 МиБ либо загружайте меньшими партиями. Изображения свыше 50 мегапикселей отклоняются. При загрузке анимированного WebP сохраняется первый кадр.

Удаление фото из галереи удаляет связь с товаром после сохранения; сам файл в `hatti_media` сохраняется, чтобы не повредить другой товар, использующий его. Незавершённые загрузки также могут оставаться в хранилище. Автоматической очистки таких файлов нет.

## Выполненные проверки

- TypeScript и production-сборка Next.js.
- Node-тесты: сохранение старых изображений, валидация галереи и цены, ошибки сортировки, декодирование/ресайз загрузки, локальное сохранение и параллельное создание.
- PostgreSQL 17 в отдельном локальном контейнере: миграция старой схемы, повторный запуск, ограничения БД, откат неверной сортировки и параллельное создание.
- Chromium: управление фотографиями и сортировкой через админку, выбор файлов и drop, удаление, сохранение цены, 401/403/400, публичная карусель и размеры 390/768/1440. В мобильном режиме проверены свайп, следующий тап, фильтрация, выбор варианта и корзина. Проверены сообщение при ошибке сортировки, повторное сохранение и обновление уже открытой главной через BroadcastChannel.

`pnpm test` запускает тест PostgreSQL только при заданном `TEST_DATABASE_URL`; разрешён только изолированный сервер на `127.0.0.1`. Тест создаёт собственную временную БД, не очищает существующие таблицы. `node tests/start-browser-fixture.cjs` запускает копию приложения на `127.0.0.1:5011` с тестовым каталогом и тестовым входом `hatti-test` / `hatti-test-only`, без чтения `.env` и рабочей БД. Артефакты — в игнорируемом `output/playwright/`.
